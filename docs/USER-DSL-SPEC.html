1. 言語の目的と Common Lisp の流儀

DSL のソースは通常の Common Lisp プログラムとして読み込み、定義マクロがその内部に書かれた HOL 構文を精密化する。利用者は S 式・パッケージ・マクロ・関数・条件・開発ツールの既存の慣習を使う。

原則仕様
通常の定義形式名前と lambda list を先に置き、任意の docstring、declare、意味を持つ本文を続ける。通常の定義を :params / :value / :statement / :proof のプロパティ列にはしない。
論理を保つHOL の型・項・定理は独立したオブジェクトである。HOL の関数定義は CL の実行可能な関数を自動生成しない。
注釈を減らす引数・結果・期待型・証明コンテキストから型制約を伝播する。明示的な型変数は ?a と書き、型名の誤記を型変数と見なさない。
拡張を自然にするCL の defmacro / macrolet と、手続的な CL 関数で書く証明補助を利用する。構文展開後の型・束縛と、返った定理の契約を検査する。
状態を説明できる成功した宣言の由来、再読込、同名定義の変更、未完了の義務、失敗による状態を明示する。
カーネルで証明する自動化・変換・ユーザー拡張も最終的に既存カーネルによる定理を返す。未証明の性質を新しい公理で埋めない。

CL の記法を共有することは評価規則まで一致させることを意味しない。外側の CL コードは通常の CL として動き、定義マクロが捕捉した HOL 本体では HOL の意味を用いる。この境界を第4・5・8節で定める。

2. 論理的基盤と信頼境界

対象は固定された HOL Light 標準コアの古典的単純型付き高階論理である。型はすべて非空であり、関数型の項は全域関数を表す。型多相は定数・定理スキーマのメタレベルの多相であり、項中の型量化や依存型を意味しない。

\(\Gamma\vdash p\)Γ⊢p\Gamma\vdash p

この判断で Γ は HOL の仮定、p は型 bool の項である。構文が型付けされたことと、その命題が証明されたことは別の状態として扱う。

標準プロファイルは元のコアが導入する INFINITY_AX・SELECT_AX・ETA_AX を基礎とする。DSL の通常の定義宣言は既存の定義的拡張または存在定理による仕様導入を用い、便宜的な公理追加で代替しない。

信頼対象には翻訳器・実行時・移植されたカーネル・起動用イメージが含まれる。LCF 型の境界を設けることは、この Common Lisp 移植の形式検証を意味しない。公開 API は定理の内部コンストラクタを公開しない。

研究用の公理的拡張は別の明示的プロファイルで扱う。通常の仮定は局所証明コンテキストに入り、定理公開時に含意として閉じられる。局所仮定と大域公理を混同しない。

本改定で CL の記法・マクロ・ロードを採用しても、この論理的基盤は変わらない。ホストで真を返す計算と HOL 定理の構築は異なり、DSL の通常の定義・証明は同じカーネルの検査を通す。

検査・登録候補 → 名前付き成果物仮定・結論・型・局所名の非脱出・残余メタ変数を検査し、成功した場合だけ公開する。

型、項、定理、ゴール、戦術、変換、簡約集合、計算集合、未完了宣言は別の種類である。CL の変数や関数が同名でも、それだけで HOL の項・定理には変換されない。

;; 外側は Common Lisp。内側の x は HOL の変数。
(holai.user:defun identity-function (x)
  (declare (type ?a x))
  x)

;; CL 側のメタ操作。QUOTE は通常の CL の QUOTE。
(holai.user:check '(identity-function 3))

コンパイル時に、利用可能な情報で構文の妥当性を検査してよい。ただしカーネルを変更する処理はロード時・明示的評価時に行う。後続の DSL 定義をコンパイルするために先行定義をカーネルへ導入する必要がないよう、未解決の参照はロード時に解決する宣言計画として保持する。

5. Reader・シンボル・パッケージと名前解決

正規ソースは UTF-8 の通常の .lisp ファイルとする。CL 標準 reader をそのまま使い、コメント、パッケージ修飾、エスケープされたシンボル、quote/backquote などを CL の規則で読む。必須の独自 readtable や .hol ローダーは設けない。load は通常の CL プログラムを実行する操作であり、入力をデータ専用言語として隔離する契約は持たない。

(defpackage #:example.trees
  (:use #:cl #:holai.user)
  (:shadowing-import-from #:holai.user
    #:defun #:defconstant #:deftype #:defstruct)
  (:export #:tree #:leaf #:node #:tree-size #:tree-size-positive))

(in-package #:example.trees)

;; 通常の CL 関数を定義する場合は明記する。
(cl:defun source-name (symbol)
  (symbol-name symbol))

holai.user は CL の defun、defconstant、deftype、defstruct と異なる DSL マクロを同名で公開する。他の CL シンボルは共有する。上記の shadowing-import が競合解決の正規形である。CL パッケージの定義セルや標準シンボル自体を書き換えない。修飾して holai.user:defun と呼ぶ方法も同等に使える。

識別子の同一性は CL シンボルの同一性による。通常の readtable-case による大文字化と |ExactName| の区別を保持する。シンボル名を一律に downcase して照合しない。新しい宣言の基底名は現在のパッケージが所有するシンボルに限る。CL:IDENTITY のような継承シンボルを自分の論理関数名に使う場合は、先に defpackage の :shadow で自分のシンボルを作る。意図せず CL パッケージへ生成名を intern しない。パッケージ修飾された局所束縛も、読まれたシンボルの同一性で判定する。

example.trees:tree
example.trees:tree-size
example.trees::tree.induction
|ExactName|
?a

型・論理定数・定理・戦術・変換・資源の登録表は種類ごとに分かれ、それぞれ CL シンボルをキーにする。項のローカル変数は同じシンボルの論理定数を隠す。定理位置では局所証明ラベルを優先する。大域参照を強制する場合は (ref example.trees::tree.induction) を使う。

名前の可視性は defpackage、import、shadowing-import、export、CL の一重・二重コロンの規則に従う。独自の (@ theory name) は使わない。生成物の tree.induction は普通の CL シンボルであり、ドットはパス演算子ではない。生成名は基底名の home package に intern し、衝突を検査する。利用者が必要な生成名を export する。

CL における defpackage の評価と、その後のフォームの読み取り順が前提である。Lisp ソース全体を初めに別パッケージで読み切ってから処理する独自ローダーは、この意味を変えてはならない。HOL 内部名との対応は衝突しない符号化と登録表で保持し、ハイフン・大小文字・パッケージを失わない。

6. 型言語・?a・declare

型変数は ?a、?b のように名前が ? で始まる CL シンボルとする。これは型位置での規約であり、reader macro ではない。型コンストラクタは登録済みのシンボルであり、未知の型名を型変数に読み替えない。

int

-> は2引数以上を取り右結合する。set は bool 値関数への透明な略記である。finite は正の固定自然数から有限添字型を表す略記であり、依存添字ではない。型はすべて飽和したコンストラクタ適用で、arity と occurs check を検査する。

型変数の明示的な量化一覧は、型宣言では名前直後の型パラメータリスト、関数・定理では任意の (declare (type-variables ?a ...)) で指定する。関数・定理で省略した場合はソースに現れる型変数と残余推論変数を安定した順で一般化する。明示一覧を与えた場合はそれ以外の型パラメータの残留をエラーにする。空の一覧は単相である。

名前付き型変数は対応する宣言中で剛体とし、多相定理を証明する途中で具体型へ特殊化して済ませない。推論で作るメタ変数とは別である。局所の値束縛は単相であり、ML の let 多相や型の高ランク量化を導入しない。

declare は捕捉された HOL 本体の宣言である。type は HOL 型制約、values は単一の HOL 結果型を指定する。複数値は HOL の返却規約に持ち込まず、必要なら積型を用いる。宣言先にない変数・未知の宣言・矛盾する注釈はエラーとする。ftype など CL 固有の型意味論を無条件には流用しない。

型略記は (deftype predicate (?a) (-> ?a bool)) の形とし、CL の deftype のように任意のホスト計算を本体として評価しない。公開された型引数順とバックエンドの型変数順との置換をアダプタが保持する。

7. 型推論、期待型、オーバーロード

推論は単純型の単一化を基本とし、occurs check、引数型、関数の結果型、束縛変数の型、既知定数の型スキーマを使用する。定数の多相型は出現ごとに新鮮化する。同じ局所変数はスコープ内で単一の型を持つ。

\(\Gamma\vdash t\Leftarrow\tau\)Γ⊢t⇐τ\Gamma\vdash t\Leftarrow\tau

期待型は外側から内側へ伝播する。命題・仮定・帰納規則の結論には bool、等式の両辺には同じ型、存在証人には対象の束縛変数の型、再帰方程式には署名からの期待型を与える。

オーバーロードはロード時の環境で固定された候補集合を制約で絞る。候補が一意なら採用する。複数の互いに異なる具体的候補が残る場合はエラーとし、候補と必要な注釈を示す。暗黙の型変換は自動挿入しない。単なる候補順で実数加算か自然数加算かを決める挙動を、正規言語の標準規則としない。

制約のない自然数リテラル単独には num を既定とする。ただし (+ x y) など、未確定の演算を含む式全体へ無条件に num を割り当てない。自然数から整数・実数への対応は、リテラルの解釈または明示的な変換で扱う。

残余の推論変数は宣言が多相化を許す場合のみ安定した順序で一般化する。定義の署名に現れない型変数が証明義務や実装側に残った場合は公開しない。局所 let は λ 展開による単相の束縛であり、ML の let 多相を持ち込まない。

項に対する高階マッチングと、型に対する単一化を区別する。exact/apply が任意の高階単一化問題を完全に解くとは規定しない。明示的なインスタンス指定を常に用意する。

積極的な推論は注釈の省略を支援する方針であり、曖昧な型の選択を無制限に推測する約束ではない。曖昧性をエラーにする規則は本版の候補とし、数値既定・候補優先順位の詳細は第30節に残す。

HOL 本体の関数適用は CL の評価規則に従わない。CL の真偽値としての非 nil、破壊的代入、例外、複数値、可変引数を数学的意味へ暗黙導入しない。関数・量化の lambda list は distinct な必須変数の一覧である。&optional、&rest、&key、&aux と destructuring lambda list は論理関数に採用しない。ホストの証明補助関数では通常の CL lambda list を使える。

9. パターン・match・全域性

パターンは変数、_、登録済みコンストラクタ適用、積・リスト、(the type pattern)、(as name pattern) とする。同じパターンの変数の重複を拒否し、等しさを条件にしたい場合は bool 式に明記する。

(match tree
  ((leaf value) 1)
  ((node left right)
   (+ (tree-size left) (tree-size right))))

分岐順はソース順で、最初の一致を選ぶ。結果型を統一し、cases 原理とパターン展開に基づいて網羅性を検査する。不完全な分岐は拒否する。任意値を意図する場合だけ最終分岐を (_ (arbitrary type)) と明記する。HOL 関数に実行時のパターン不一致例外を想定しない。

通常の defun の match は順序を持つ。一方、第14節の defequations は全方程式を同時に要求するため、重複には互換性の証明が必要である。CL の case のように全型で eql 判定できる機構は自動導入しない。

10. 定義形式・docstring・宣言・生成名

通常の宣言は名前、引数または型パラメータリスト、任意の docstring、0個以上の declare、本文の順で書く。docstring は先頭に1個だけ認める。HOL の項本体は1式であり、暗黙の progn は設けない。定理では命題1個の後に1個以上の証明手順を置く。帰納定義・相互定義などの本文は種類ごとの節で定める。

decl-spec を持つ宣言は、未知の宣言・同じ単値指定の重複・互いに排他的な指定をエラーにする。type の重複は同じ制約なら許し、不整合なら拒否する。docstring と宣言は論理的命題の一部ではないが、診断・由来と合わせて記録する。

成果物命名と契約
関数・定数name.definition を定義定理とし、name.equations を利用可能な方程式群にする。非再帰でも両者を参照可能にする。
データ型type.induction / .recursion / .cases / .injective / .distinct。存在しない単射性・非交差性は偽の空定理を作らず未生成とする。
名前付き規則relation.rules、relation.rules.rule-name、relation.induction、relation.cases。ソースの規則名を保持する。
パッケージ基底シンボルと同じ package に生成する。基底シンボルの名前の大小文字を保持し、接尾辞は通常の CL 表記と一致する大文字の .INDUCTION 等を付ける。
公開生成名を勝手に全 export しない。defpackage/export で管理し、inspect-definition が生成物を一覧する。
CL の格納先論理定義の名前は種類別の DSL 登録表に入る。CL の関数セル・値セルに同名の数学オブジェクトを暗黙格納しない。

全生成名を事前に列挙し、既存の異なる宣言の成果物と衝突すれば導入前に拒否する。成功した同一宣言の再読込と、意味を変更した同名定義を区別する。第25節の定義同一性に基づいて再利用する。

11. defun・defconstant・deftype・存在仕様

(defun identity-function (x)
  "Return the argument."
  (declare (type ?a x))
  x)

(defconstant empty-numbers
  (the (list num) (list))
  "The empty list of natural numbers.")

(deftype predicate (?a)
  "Predicates over ?a."
  (-> ?a bool))

(defspec (chosen-element) ()
  (declare (type-variables ?a))
  (exists (x)
    (declare (type ?a x))
    (= x x))
  (witness (arbitrary ?a))
  (refl))

defun は非再帰・再帰の双方を扱う。引数順で本体を λ 抽象した定数を導入する。自由項変数は引数か、明示された外側の証明コンテキストの変数に限る。CL の closure をそのまま数学的定義へ取り込まない。

defconstant は CL と同じ (defconstant name term [docstring]) の形を採る。term に自由項変数は許さない。型は the と期待型から推論し、必要な型多相は一般化する。CL の定数変数を作る操作ではない。

deftype は名前・型パラメータリスト・任意 docstring・型式1個という透明な型略記である。循環を拒否する。新しい非空型を導入する宣言ではない。

defspec は名前リストと必須の空 lambda list を取り、docstring/declare の後に閉じた存在命題1個、その証明手順を置く。存在定理の先頭の存在変数と名前を順に対応させ、すべて消費する。仮定・自由項変数・名前数・重複・型を検査して元の new_specification を用いる。本版では prefix の部分消費を公開しない。

存在仕様は一意性・計算可能性・網羅的な計算規則を保証しない。外側の項パラメータに依存する仕様を作る場合は、Skolem 化や引数化をカーネルの定理変換で実際に証明する。量化順序の交換を構文置換で済ませない。

13. 帰納的関係・相互帰納・帰納的集合

(definductive even (n)
  "The least relation closed under these rules."
  (declare (type num n))
  (zero ()
    (even 0))
  (step (k)
    (implies (even k) (even (+ k 2)))))

(defrelations parity ()
  (parity-even (n)
    (declare (type num n))
    (zero () (parity-even 0))
    (step (k) (implies (parity-odd k) (parity-even (succ k)))))
  (parity-odd (n)
    (declare (type num n))
    (step (k) (implies (parity-even k) (parity-odd (succ k))))))

definductive は関係名、引数 lambda list、docstring/declare、1個以上の規則節を取る。結果型は bool に固定する。引数リストは関係の arity と署名を記述するもので、各規則の変数を暗黙に束縛しない。規則節は (rule-name (variables...) declaration* proposition) で、変数は規則ごとに独立し、最後の命題を全称閉包する。署名の型変数は宣言全体で共有する。

規則の命題は前提を含む含意または基底の結論である。結論の頭は定義対象の関係でなければならない。規則から最小の閉じた関係を構成し、導入・帰納・反転原理を生成する。含意を無検査に公理として追加しない。

defrelations は群名、共通パラメータ lambda list、docstring/declare、関係節の列である。関係節は definductive の名前以降と同じ形を持つ。群のパラメータは各関係の引数列に先行する共通の固定引数として引数化し、各規則で一貫して用いる。単独の関係で共通パラメータが必要なら1関係の defrelations を使える。

単調性をまず自動証明し、残余条件があれば義務として通知する。(declare (monotonicity-proof proof-form)) を指定してよい。証明形式は第18節の by/proof を用い、必要な仮定を元の存在定理へカーネル推論で組み込む。未証明の仮定が残った結果を公開しない。

(declare (strong-induction t)) により強い帰納原理を要求できる。既定は nil。生成名は even.rules、even.rules.zero、even.rules.step、even.induction、even.cases とする。相互群の原理は群名の下に置き、各関係へ導出可能な成分だけを付ける。

definductive-set は definductive と同じ形で、論理定数を集合として公開する派生形である。bool 値関数であることを使い、導入・帰納・反転の表示を所属表記にする。一般的な最大不動点や余帰納の別名にはしない。

14. defun による再帰・相互再帰・停止性

(defun tree-size (tree)
  "Count the leaves."
  (declare (type (tree ?a) tree)
           (values num))
  (match tree
    ((leaf value) 1)
    ((node left right)
     (+ (tree-size left) (tree-size right)))))

;; 自動証明だけでは不足する場合に補助情報を宣言できる。
(defun copy (n)
  (declare (type num n)
           (values num)
           (measure n))
  (if (= n 0) 0 (succ (copy (- n 1)))))

(deffunctions mutual-parity
  (is-even (n)
    (declare (type num n) (values bool))
    (if (= n 0) t (is-odd (- n 1))))
  (is-odd (n)
    (declare (type num n) (values bool))
    (if (= n 0) nil (is-even (- n 1)))))

自己参照は defun の本体から認識する。通常の再帰に :recursion 指定や別の defrecursive 宣言を要求しない。既存のデータ型再帰原理・一般定義機構により、型、分岐、再帰呼出の条件を計画として精密化する。

任意の decl-spec契約
(recursion theorem-reference)明示した再帰原理を使う。推論で適切な原理が得られる場合は不要。
(termination :auto)既定。存在と停止に必要な条件の自動証明を試みる。
(measure term)引数をスコープに含む num 値の測度。引数を λ 抽象して関数にし、各呼出での減少を証明する。
(well-founded-relation term)引数タプル上の関係。整礎性と各呼出の減少を証明する。
(obligation-proofs (label proof-form) ...)精密化で生成した義務への明示的な証明。ラベルとコンテキストを検査する。

termination、measure、well-founded-relation は排他的である。指定がないときだけ termination :auto を補う。原理の指定 recursion とこれらの組合せは、原理がすでに要求を満たす場合も含めて検査し、利用されない指定を黙って捨てない。

通常の defun には網羅的な本体が必要であり、不完全な match を許さない。一般再帰では整礎性・減少性・分岐条件・関数の存在に必要な義務を実際に証明する。失敗は非停止性の証明ではない。義務が残った宣言計画は調査できるが、その関数や定理を後続の確定定義・計算で使えない。

deffunctions は群名、任意 docstring、2個以上の関数節を取る。節の形は defun の名前以降と同じで、同時に署名を推論する。適切な同時再帰原理を使うか、同時存在を実際に証明して new_specification に渡す。単一関数用 define を順に呼ぶだけで一般相互再帰を実現したとは扱わない。群全体の補助宣言は docstring の直後の declare に置く。

数学的な方程式による定義には defequations を別途用意する。形は (defequations name (args...) declaration* (label (vars...) declaration* equation) ...) とする。各節の equation は当該関数を頭に持つ LHS と RHS の等式で、LHS パターンの網羅性と重なりの互換性を要求する。節順に優先度はない。部分的な性質だけを指定する用途は defspec が担う。

生成物の name.definition は証明した定義の根拠、name.equations は利用可能な計算方程式の束とする。ラベル付き方程式は name.equations.label も公開する。構造再帰・自然数・一般測度・相互群それぞれで実際に方程式と帰納法を使う適合シナリオを定める。

\[\operatorname{class}(x)=\operatorname{class}(y)\iff R(x,y)\]class(x)=class(y)⇔R(x,y)\operatorname{class}(x)=\operatorname{class}(y)\iff R(x,y)

この定理を含む公開 API を提供する場合は、元の型の往復定理と同値関係の証明から実際に導く。利用者向けの .class と、元の代表集合に対する abs/rep の型を区別する。

deflift は対象関数、持ち上げる引数位置、商の束、well-definedness の証明を指定する。結果が元の型か商型かを署名で固定する。lift-theorem は元の lift_theorem の対応範囲で定理変換を行い、変換できない高階の形はエラーとする。任意の式を無条件で移送する仕組みとはしない。

本節の正規ヘッダは、defsubset/defquotient では名前・型パラメータリスト・docstring・declare である。本文はそれぞれ「基底型上の述語と非空性証明」「基底型上の関係と同値性証明」の2形式に固定する。representation-type は必須である。証明は定理参照か by/proof 形式を取る。

deflift は名前・引数リスト・docstring・declare・元の関数を表す項・well-definedness 証明の形とする。quotients と lift-positions は必須で、位置は1始まり。引数・結果の型は推論可能なら省略できるが、商に対応する基底と結果の対応は一意でなければならない。複数の商を用いるときの位置対応の完全なスキーマは第30節の未確定事項とする。

16. defthm・lemma・公開時の閉包

(defthm implication-identity (p)
  "Every proposition implies itself."
  (declare (type bool p))
  (implies p p)
  (assume h)
  (exact h))

(defthm reflexivity (x)
  (declare (type ?a x))
  (= x x)
  (refl))

(defthm tree-size-positive (tree)
  (declare (type (tree ?a) tree))
  (>= (tree-size tree) 1)
  (induct tree)
  (simp tree-size)
  (asm-arith))

defthm は名前、必須のパラメータ lambda list、任意 docstring、declare、命題1個、1個以上の証明手順という順に書く。空のパラメータリストも明記する。命題の型は bool である。:statement / :proof の必須ラッパーは廃止する。

パラメータは証明中には固定された局所変数であり、初期ゴールへ先に forall を挿入しない。公開時に外側コンテキストの仮定を含意として閉じ、許可された外側パラメータと lambda list の変数を指定順で全称化する。明示的な forall は命題自身の一部なので、通常の全称導入で証明する。

未束縛の項名を黙ってパラメータに追加しない。lambda list、命題内の binder、外側の明示的コンテキストにない名前は、登録済み定数として解決できなければエラーとなる。型の推論と、誤記された項変数の暗黙導入を区別する。

\[\vdash\forall\vec{x}.\;H_1\Rightarrow\cdots\Rightarrow H_n\Rightarrow p\]⊢∀x→.H1⇒⋯⇒Hn⇒p\vdash\forall\vec{x}.\;H_1\Rightarrow\cdots\Rightarrow H_n\Rightarrow p

公開する HOL 定理の仮定リストは空でなければならない。期待結論・型変数の一般性・局所変数の非脱出・未解決のメタ変数を検査する。多相命題の特殊例だけを証明して一般命題として登録しない。

証明手順列は then の逐次合成として扱い、各手順をその時点のすべての残余ゴールへ適用する。枝別の処理には thenl/focus/branch を明示する。証明終了後の余分な手順を黙って捨てず、構文検査し、通常の逐次合成と同じ資源・診断規則で扱う。

lemma は同じ形式で with-proof-context 内の局所定理を作る。ブロック外へ自動公開しない。defthm が登録することと CL の export は別であり、外部参照の可視性は package に従う。

17. 定理式と推論規則

定理式意味

(inst th :types ((?a τ) ...) :terms ((x t) ...))型・項の明示的インスタンス。捕獲回避と型整合性を検査。
(spec th t ...)全称量化の特殊化。型インスタンスが必要なら推論する。

数千の標準定理に個別の新構文は不要である。CL シンボルをキーとする名前解決で参照し、定理式・書換え・自動探索へ渡せるようにする。

定理を期待する DSL 位置の裸のシンボルは定理参照であり、CL の変数評価ではない。外側の CL から定理オブジェクトを取得する API は (theorem 'example.trees:tree-size-positive) とする。手続的な補助手続はこの明示 API と型付きの項・定理操作を用いる。

18. 証明ブロック・局所コンテキスト

(defthm implication-identity (p)
  (declare (type bool p))
  (implies p p)
  (proof
    (assume h p)
    (have identity p
      (exact h))
    (show p
      (exact identity))))

定理本体では戦術列を直接書ける。証明を1形式にまとめる位置では (by tactic...) または (proof step...) を用いる。by は逐次戦術、proof は局所ラベル・明示した命題・下位証明を持つ構造化ブロックである。

ステップ契約
(fix x ...)ゴールの全称束縛を指定名で導入する。型は束縛と宣言から得る。外側パラメータを再定義しない。
(assume label [proposition])含意の前件を導入し、命題を与えた場合は一致を検査する。任意の強い仮定を無条件に追加しない。
(have label proposition proof-step+)現在のコンテキストで別の義務を証明した後に label を追加する。自身の証明中に label は見えない。
(show proposition proof-step+)現在ゴールと命題の一致を検査し、下位手順を適用する。
(obtain (vars...) theorem-reference ((label proposition)...))存在除去。変数の新鮮性と非脱出を検査し、対応する仮定に名前を付ける。
(calc term (= next proof-step+) ...)各段階の等式を証明し推移律で連結する。他の関係は登録済み推移規則がある場合だけ許す。
(branch label (vars...) proof-step+)ケース・帰納の名前付き分岐に対応する。変数の個数と型を検査し、分岐不足・重複を拒否する。

show の命題の一致は α 同値を基本とする。βη 等の差を認める場合はその変換の証明を経由する。ブロック終了時の残余ゴールやメタ変数を未記載の穴として成功扱いしない。

局所の型・変数・仮定の共有には第23節の with-proof-context を使う。証明内の let として CL 値を評価する escape は設けず、必要な手続的拡張は名前付きの戦術・規則・変換として第24節の境界で登録する。

(then (simp) (try (assumption)))
(thenl (split) (refl) (refl))

(focus base (simp))

then は左から右へ合成し、次の手順をすべての残余ゴールへ適用する。thenl は生成されたゴール数と枝数の完全一致を要求する。focus は安定したラベルで対象を選ぶ。利用者が数値インデックスを使う場合は 1 始まりとし、その時点の一覧に対して解釈する。

orelse/try は通常の「この戦術では解けなかった」という失敗だけを処理する。構文・型・名前の誤り、資源上限、利用者割込み、内部エラーを通常の失敗へ変換しない。枝の失敗ではゴールとメタ変数の代入状態を元に戻す。探索済みの資源使用量は元に戻さない。

repeat はゴールと代入状態に進展がない場合に反復を止める。単純な成功回数だけで進展と判定せず、repeat skip が無制限に続く仕様にしない。すべての自動化は明示的または環境で固定された上限を持つ。

最終的には既存の prove の仮定・結論検査を行う。外側のコンテキストがある場合は、仮定とパラメータを閉じる前の判断を保持したうえで、公開時の閉包を検査する。

戦術呼出は CL に馴染む関数形とし、引数なしも (refl)、(assumption) と書く。一般の戦術参照を合成子へ渡す位置では名前単独も使える。(induct tree) は変数の型から原理を選び、複数候補があれば :using を要求する。

20. 書換え・簡約集合・位置指定

(rewrite tree-size)
(rewrite h :at (hypothesis k) :orientation :backward)
(simp tree-size)
(asm-simp tree-size)
(simp :using (tree-size.equations) :set arithmetic)

(defsimpset arithmetic
  "Rewriting rules for this development."
  (extends core)
  (rewrites addition-zero multiplication-one)
  (congruences)
  (condition-provers))

rewrite/simp/asm-rewrite/asm-simp は、先頭の0個以上の定理または定義名を短縮指定として受け取る。論理関数名を与えると、その宣言の .equations を明示的な登録情報から選ぶ。基底名と定理名がともに解釈できる場合は曖昧性エラーとし、完全な生成名または ref を要求する。

定理列の後に :using、:at、:orientation、:repeat、:set などのキーワード引数を置く。短縮定理列と :using の併用は拒否する。未知・重複キーも拒否する。方向は :forward / :backward、回数は :once / :repeat とし、rewrite の既定は :forward、:once、対象 goal である。simp は仮定を用いず、asm-simp は用いる。

位置は goal、(hypothesis label)、(subterm target path) とする。path は rator/rand/body の列で、存在しない経路はエラー。パターンによる occurrence が一意でなければラベルか1始まりの番号を要求する。

条件付き書換えでは条件を証明してから適用する。証明できない規則は適用しない。strict 指定時には未解決条件を報告する。仮定の含意付き書換えと極性は元の手続が証明する変換に従う。

defsimpset は名前・任意 docstring・種別付き節を取る。extends/rewrites/congruences/condition-provers はそれぞれ高々1節、未指定は空とする。結果は不変の資源である。AC 規則・ループ抑制・順序も資源設定として保持し、import や定理参照でセッション全体の簡約設定を暗黙変更しない。定理の (declare (simp t)) は明示的な局所コンテキストでのみ収集し、その外へ漏らさない。

21. 変換・正規化・証明付き計算

変換は入力項を受け取り、その項と結果項の等式を証明した HOL 定理を返す。

\[\vdash t=u\]⊢t=u\vdash t=u

公開する計算用変換は仮定を持たず、入力と等式左辺の α 同値、両辺の同型性を検査する。文脈付き変換が仮定を必要とする場合は別の種類として登録し、その仮定を呼出コンテキストで証明する。

(conv beta)
(conv (depth beta))
(conv (then-conv beta (rewrite-conv h)))
(compute :set evaluator :restricted (tree-size))

(defcompset evaluator
  "Equations used for proof-producing evaluation."
  (extends bool-computation)
  (equations tree-size.equations)
  (conversions num-reduce)
  (strategy :cbv))

最低限、β・η・α調整、rator/rand/body、深さ方向、1 回／反復、逐次・選択、書換え変換、数値・整数・実数有理値の還元を登録する。normalize は使用する正規化手順を明示し、全高階論理の正規形判定を保証しない。

計算集合は方程式・変換・停止名・戦略を持つ不変の資源とする。通常の CBV、weak/restricted 評価を元の Compute パッケージへ接続する。再帰方程式が定義されたという事実だけで、計算が必ず停止すると仮定しない。評価の結果に残余項があればそのまま表示し、数値になったと偽って報告しない。

新しい外部の計算器や決定手続を登録する場合も、出力の正しさを元の推論で再構成する契約を持たせる。通常の数値を返すホスト関数を、そのまま証明用変換として登録しない。

defcompset の節は extends/equations/conversions/strategy/stops とし、それぞれ高々1個。リスト節の省略は空、strategy の既定は :cbv である。CL 関数をコンパイルして得た実行結果と、等式定理を返す証明付き評価を区別する。

パッケージは名前と可視性、ASDF system はファイルとロード順・依存を管理する。いずれも論理的な公理の集合を表すものではない。新しいパッケージを作ってもカーネルの型・定数・公理状態を分離しない。必須の deftheory/import/open や sealed 理論の独自ローダーは設けない。

with-proof-context は引数リスト、declare、宣言列を持つ CL マクロである。type、type-variables、assumption、simpset、compset、automation をコンテキスト設定として扱う。入れ子にでき、局所変数・仮定・lemma・設定を終了時に破棄する。defthm はそこで証明した内容を外側パラメータと仮定について閉じてから登録する。

局所仮定に依存する定義を無条件に大域定数として導入しない。コンテキスト内の論理定義は、必要な項パラメータを引数化し、仮定から独立した存在・定義が証明できる場合だけ許す。条件付きの存在仕様なら、条件を持つ適法な定理を明示して扱う。

ソースは load、コンパイル物は compile-file 後の load、依存管理は ASDF を用いる。ASDF のコンパイル段階とロード段階は第4節に従う。DSL が任意の eval-when の意味を変更することはない。明示的にトップレベルで論理操作を評価すれば、その時点で実行される。

通常の CL ソースには任意のホスト計算があるため、すべてを自動 replay 可能とはしない。再構築にはソース・ASDF の版・ホスト拡張・設定・初期イメージを固定する。CL の package export は論理的な前提を取り除くものではない。

24. 通常のマクロ・手続的な証明拡張

;; 通常の Common Lisp マクロを HOL 構文で使う。
(defmacro implies* (p q)
  `(implies ,p ,q))

(defun same-test (x)
  (declare (type num x))
  (implies* (= x 0) (= x 0)))

;; CL マクロの慣習どおり、内部の束縛には gensym を使う。
(defmacro twice (value)
  (let ((temporary (gensym "VALUE")))
    `(let ((,temporary ,value))
       (+ ,temporary ,temporary))))

CL の defmacro / macrolet を構文拡張の標準手段とする。外側の CL は通常の macroexpand を用いる。捕捉した HOL 本体では、組込みの HOL 構文を先に認識し、その構文の本体位置だけを再帰的に処理する。CL の and/let/cond 等の組込みマクロをそのまま CL の内部形へ展開しない。

HOL の特殊構文・登録済みコンストラクタ・論理定数の呼出を先に解決し、それ以外の頭が利用可能な CL マクロなら展開する。論理定数とホストマクロを意図せず重ねない。明示したマクロ優先の選択機構を追加するかは第30節に残す。展開は型推論より前に行い、展開回数と資源の上限を持たせる。macrolet のレキシカル環境をトップレベル宣言マクロから受け渡す。

通常の CL マクロに衛生性を自動保証しない。シンボルのパッケージと gensym を保持し、捕獲を避ける責任は CL の慣習どおりマクロ作者にある。展開後の HOL の束縛・自由変数・型・生成物を DSL が検査する。ソース読込時の一時的なパッケージ状態や外部の可変値へ依存する展開は、その依存を由来へ記録する必要がある。

手続的な規則・戦術・変換は、CL で書いた関数を明示的な登録境界に渡す。defrule、deftactic、defconversion は、名前・通常の CL lambda list・docstring・CL 宣言・CL の本体という形を取る。これらの本体はホスト CL として評価される。論理 defun の HOL 本体とは種類が異なる。

拡張返却契約
defrule入力の型・項・定理に対してカーネルで構成した定理を返す。仮定と結論を検査する。
deftactic戦術オブジェクトを返す。ゴールをサブゴールと正当化関数に変換し、再構成後の定理を検査する。
defconversion入力項と結果項の等式定理を返す。左辺・型・仮定の契約は第21節に従う。

拡張の引数に渡される term/theorem/tactic 等は型付きオブジェクトであり、S 式を勝手に eval して定理化しない。登録時の引数種別・期待型・返却契約の指定方法と、戦術構築 API の全シグネチャは第30節の未確定事項である。ここを埋める前に実装開始可能とはしない。

元の公開束縛への接続は、所有パッケージ、関数か関数値か、arity、入出力、効果、失敗、資源を持つ descriptor で管理する。Compute の子パッケージや同名別束縛も区別する。ホスト拡張は通常の CL コードとして実行権限を持ち、悪意ある CL コードからカーネルの内部状態を防護するセキュリティ境界を主張しない。

25. 宣言登録・再読込・失敗・再定義

通常の開発は同一 Lisp プロセスの REPL と load/ASDF で行う。全操作を専用 worker の中に閉じる方式は必須にしない。新しい論理的名前を導入する前に、構文・名前衝突・型・可能な存在義務を検査し、宣言計画を作る。

成功した定義の登録は、すべての必要な定理と生成名を検査してから行う。未完了の計画は pending として保持し、確定した関数・型・定理の根拠に使えない。proof の失敗だけなら旧い定理の登録を保存し、新しい候補で上書きしない。

操作意味
同一宣言の再読込解決済みのシンボル参照・型・正規化した論理本体・設定・基盤の一致を確認し、既存のカーネル定義を再利用する。docstring や空白だけの変更は論理的再定義にしない。
異なる定義を同じ名前へロード型・論理定数の意味は上書きしない。definition-conflict を通知する。通常の続行操作で強制上書きする restart は提供しない。
定理の再証明同じ命題を再証明した場合は検査後に参照を更新できる。異なる命題への置換は既存依存を曖昧にしない版管理方針が必要で、第30節で確定する。
戦術・マクロの再定義通常の CL の再定義に従う。既存の定理は変わらないが、その後の証明の由来には新しい拡張の版を記録する。
カーネル変更後の失敗元の定義手続は途中で型・定数を追加する可能性がある。フロントエンド表だけ戻して論理状態が復元したとは報告しない。

バックエンド呼出後に失敗して状態の完全性を保証できない場合、kernel-state-uncertain を通知する。そのカーネルでは新しい定義導入を停止し、クリーンなイメージからの再起動・再ロードを必要とする。定理と型の状態を確認できたという証拠なしに「やり直し可能」と扱わない。

任意の CL ソースの副作用を含む自動 rollback/replay は保証しない。任意機能として別プロセスでビルド・検証することは可能だが、既定の同一プロセスでの意味と失敗の扱いを置き換えない。SBCL ダンプは起動最適化であり、カーネルの復元契約は別に検証する。

戦術分岐の失敗ではゴール・代入・局所ラベルを巻き戻す。探索の資源消費は巻き戻さない。組込み戦術は新しい型・定数・公理を導入しない。手続的な拡張で論理的状態を変更する経路は許可された戦術契約に含めず、検出・無効化の方針を接続仕様で確定する。

これらは通常の CL 関数であり、構文データには quote を付ける。CL:STEP との衝突を避け、対話的な1手の適用は proof-step と呼ぶ。論理定義マクロ内部の手順には quote を付けない。check は型・自由変数・型パラメータ・オーバーロードの選択を返す。check/goal は調査用に未束縛名を自由変数として表示できるが、名前付き宣言の自由変数規則を変更しない。

27. ソース・FASL・イメージ・由来・公理

再構築の一次資料は .lisp ソース、ASDF の依存と版、固定 HOL コア、ホスト拡張、ロード時の設定である。FASL は論理宣言計画をロードするコンパイル物であり、カーネルを超えて移植できる独立した証明書ではない。

定理の仮定と結論だけから、検査済み theorem オブジェクトを逆直列化して作る API は提供しない。イメージ・キャッシュは元のカーネル、翻訳器、実行時、拡張、構築履歴の信頼範囲に属する。別の基盤では証明を再実行する。

記録する由来はソース、マクロ展開結果、シンボルの home package、解決済み参照、型スキーマ、推論方針、証明手順と拡張の版、生成物、条件と診断である。シンボルの EQ だけを永続識別子にしない。gensym を含む束縛は識別子で正規化し、再ロードで fresh なシンボルが生じても α 同値な宣言を比較できるようにする。

元の定理オブジェクトは通常、仮定と結論を保持し、詳細な証明項や最小公理依存集合を持たない。DSL の記録する参照グラフは証明に使った宣言の由来であり、論理的な最小依存集合とは異なる。追跡できない既存定理の依存は基礎プロファイルを含む保守的な上界として表示する。

研究用の公理的拡張は別の明示的コンテキスト (with-axiomatic-extensions () ...) で扱う。内部の declare-type、declare-constant、defaxiom は新たな型・定数・公理を導入した事実を全成果物の由来に残す。ブロック終了で公理がカーネルから消えるわけではない。通常の証明の仮定は局所コンテキストに置き、定理公開時に閉じる。

通常の定義で admit/sorry/公理による自動穴埋めは行わない。pending の計画は保存できるが、確定した証明の依存先にはならない。公理宣言の正式な構文と許可する起動プロファイルは第30節で詰める。
